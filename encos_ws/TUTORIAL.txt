ENCOS 二代关节电机 | USB‑CAN 与可选 ROS 2 工具
====================================================

当前实际使用链路为 USB‑CAN 串口收发 → encos_core 协议编解码 → 终端或 ROS 2。
分析仪已验证 USB‑CAN 模块双向转发。重整后的 C++ 主链路用伪终端验证，
真实电机的问答、写入与运动均需按现场验收范围分别确认。

1. 构建
-------

目标环境为 Ubuntu 24.04 和 C++17。以下命令在工程根目录运行。

1.1 只用 C++ 和命令行

安装 g++、CMake 后，可独立构建 core 和 tools。串口功能使用 Linux termios。

  cmake -S src/encos_core -B build/native/core \
    -DCMAKE_DISABLE_FIND_PACKAGE_ament_cmake=ON -DBUILD_TESTING=ON \
    -DCMAKE_INSTALL_PREFIX="$PWD/build/native/install"
  cmake --build build/native/core --parallel 3
  ctest --test-dir build/native/core --output-on-failure
  cmake --install build/native/core

  cmake -S src/encos_tools -B build/native/tools \
    -DCMAKE_DISABLE_FIND_PACKAGE_ament_cmake=ON -DBUILD_TESTING=ON \
    -DCMAKE_PREFIX_PATH="$PWD/build/native/install" \
    -DCMAKE_INSTALL_PREFIX="$PWD/build/native/install"
  cmake --build build/native/tools --parallel 3
  ctest --test-dir build/native/tools --output-on-failure
  cmake --install build/native/tools

  usb_can="$PWD/build/native/install/lib/encos_tools/encos_usb_can"

1.2 使用 ROS 2 Jazzy

假定 ROS 2 Jazzy 软件源已配置，缺少依赖时由操作者安装：

  sudo apt install build-essential cmake python3-colcon-common-extensions \
    ripgrep ros-jazzy-ros-base ros-jazzy-rosbag2 \
    ros-jazzy-rosbag2-storage-default-plugins ros-jazzy-rosidl-default-generators

在新 Bash 中构建五个包：

  source /opt/ros/jazzy/setup.bash
  colcon --log-base build/colcon-build-log build --base-paths src \
    --build-base build/usb --install-base install/usb \
    --cmake-args -DCMAKE_BUILD_TYPE=RelWithDebInfo -DBUILD_TESTING=ON
  source install/usb/local_setup.bash
  usb_can="$PWD/install/usb/encos_tools/lib/encos_tools/encos_usb_can"

2. 接线、权限与串口收发
--------------------

2.1 模块与分析仪

先在电机断开的状态下验证。按两台设备的说明连接 CAN_H、CAN_L，
确认参考地或隔离及终端，分析仪的 CAN 帧型和波特率要与模块配置一致。
以下用已验证的标准帧串口封装。115200 是 PC 与模块间的串口波特率。

  lsusb -d 1a86:7523
  ls -l /dev/serial/by-id/ /dev/serial/by-path/
  id -nG
  stat -c '%U:%G %a %n' /dev/ttyUSB0

预期 CH340 芯片 USB ID 为 1a86:7523，设备组通常是 dialout。如果缺组，
现场操作者加组并注销后重登，也可以临时用 newgrp dialout。避免多个程序
同时打开同一个串口。找到实际路径后设置：

  sudo usermod -aG dialout nuc

  serial_dev=/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0

如果由 by-id 识别不了多个 CH340，根据 USB 插口从 by-path 选正确设备。
也可设置 serial_dev=/dev/ttyUSB0。以下各命令复用它。

2.2 打开串口持续收发

关闭正在占用同一设备的监听程序或 ROS 节点，再启动会话：

  "$usb_can" "$serial_dev"

显示 Listening on 后，电脑已经在读串口。此时可以让分析仪以 10 Hz
发送 ID 0x001、DLC 8、数据全零的标准帧。即使键盘没有输入，也应看到
RX 001#0000000000000000 undecoded。发有效的 ENCOS 反馈时同时显示已解码的字段。

在该会话内一行一条输入，只有按回车提交命令才发帧：

  DISCOVER
  QUERY 1 VERSION
  POS 1 30
  HELP
  EXIT

每条 CAN 指令写入一次，会话继续收帧。EXIT、Ctrl+D 或 Ctrl+C 关闭串口。
TX CAN 表示已写串口，是否上 CAN 总线以分析仪抓包为准。EXPECTED_REPLY
显示协议定义的反馈种类。会话直接显示收到的报文，不把任意同类帧标成匹配的
事务应答。和近期发送帧完全相同的接收帧会标记 possible_tx_echo。需要设备
回复匹配、超时或 UUID 拼接时，用第 2.4 节的只读查询。

只想发一帧时，可将命令接在设备路径后：

  "$usb_can" "$serial_dev" POS 1 30 10 0.5 2

这种调用发完退出，关闭后的反馈不保证缓冲到下次打开。使用之前的 Bash
别名时，用下面一行更新；encos 不带参数进入会话，encos POS 1 30 发一帧即退出。

  alias encos='"$usb_can" "$serial_dev"'

POS 的参数顺序为电机 ID、输出端绝对目标角度（度）、速度上限（rpm）、
相电流上限（A）、ACK。ACK 0 表示不要求回复，1、2、3 选择相应反馈类型。
省略后三项时，POS 1 30 展开为 20 rpm、1 A、ACK 2。
位置模式把 30° 写成 float32，速度和电流按 10 倍缩放后与模式、ACK 拼成 8 字节。
分析仪预期看到 CAN 0x001、DLC 8、数据 28 3E 00 00 00 32 00 2A，
PC 串口写入 AA 00 01 0D 28 3E 00 00 00 32 00 2A 7A。
当前 USB‑CAN 封装支持经典标准帧，CAN FD+BRS 实物封装待确认。

手册第 7–9 章中已有编码的指令均可逐条手动发送。完整用法见 --help：

  DISCOVER、QUERY、SET_ID、RESET_ID、ZERO [偏置]   ID 和零点管理、查询
  POS、VEL、MIXED、CURRENT、TORQUE                 各控制模式
  DAMPING、DISSIPATIVE、REGENERATIVE               变阻尼、能耗和再生制动
  ELECTROMAGNETIC_BRAKE、BRAKE                     两种抱闸报文
  CONFIG                                          参数配置，包括分段 Kt

MIXED 要求在命令末尾显式填写五对量化范围。它的角度和速度使用 rad、rad/s，
与手册的混控示例一致。CONFIG POSITION_RANGE 和 VELOCITY_RANGE 同样使用
rad、rad/s，ZERO 和 CONFIG ZERO_OFFSET 的偏置用度。混控按命令输入的
范围量化。涉及运动和写配置的真机操作遵照 AGENTS.md 的现场核验要求。

手册 V1.19EAP 的 §5.2（印刷第 10 页）描述了上位机的电机使能开关，
§7–11 未定义独立的使能 CAN 帧。ENABLE 1 会报告缺少协议定义。
完整命令、参数和反馈对应关系见第 2.5 节。

2.3 监听

  "$usb_can" "$serial_dev" monitor 5

监听用 115200、8N1、无流控打开串口，不会发查询。
分析仪发标准 ID 0x0001、DLC 8、全零数据时，预期终端显示：

  RX 001#0000000000000000 undecoded

这个报文已通过串口封装校验，数据不是可用的 ENCOS 反馈，仍会保留原始字节。
解析器在输入出现噪声、错误长度或校验失败时重新找帧头，能处理分段和连包。
先前分析仪实测连续 4 秒收到 40 帧，约 10.00 Hz。刚打开串口捕获过 33 个
额外字节，稳定后 3 秒收到 30 帧，期间无额外字节。

2.4 单次 ID 查询和只读参数

电机断开、模块仅接分析仪时，由现场操作者先启动分析仪抓包，再执行：

  "$usb_can" "$serial_dev" DISCOVER --allow-query

预期串口写入 AA 07 FF 09 FF FF 00 82 39，分析仪显示标准 ID 0x7FF、
DLC 4、数据 FF FF 00 82。只有分析仪时，工具可能在 500 ms 后返回 query timed
out，这表示串口没收到符合查询条件的电机回复。分析仪抓包用于判断发送方向。
若分析仪主动模拟 ID 1 的发现回复，CAN ID 仍是 0x7FF，数据为 FF FF 01 00 01，
终端应显示 motor_id=1。已有实物抓包确认了 NUC 发出的查询帧。

开始真实电机查询前，按 AGENTS.md 确认厂家给出的具体型号供电范围、接线和终端。
数据手册的 72 V 与调试手册的 20–57 V 存在冲突，供电在书面确认前保持禁用。
获现场只读授权后，可按实际 ID 发单项参数查询。
下面用已知 ID 1 示意，数字参数使用十进制：

  "$usb_can" "$serial_dev" QUERY 1 VERSION --allow-query
  "$usb_can" "$serial_dev" QUERY 1 POSITION --allow-query

30 为版本，1 为位置，2 为速度，3 为相电流，29 为 MCU UUID，36 为分段 Kt。
小写 discover、query 和十进制查询码仍可用。查询 36 额外传组号，如
QUERY 1 KT_SEGMENT 2 --allow-query。编码、单位及争议项见
docs/protocol_coverage.md。--allow-query 只白名单放行 ID 发现与手册已确认的参数查询。
单次请求发送后有界等待、过滤精确回显并匹配回复。失败时不会自动重发。
串口包不带物理 CAN 硬件时间戳，终端和 ROS 使用主机读取时刻。

以下节号和页码均来自《ENCOS 调试技术手册 V1.19EAP》，页码为印刷页码。
终端参数 ID、数字型参数代码和组号用十进制。分析仪显示的 CAN ID 与数据
字节为十六进制。管理命令的帧 ID 固定为 0x7FF，其余发送帧使用电机 ID。
当前串口链路使用标准经典 CAN 数据帧。

2.6 从工程根目录运行 demo

先按第 1 节编译。已按第 1.2 节安装时，在工程根目录执行：

  ./install/usb/encos_tools/lib/encos_tools/encos_usb_can /dev/ttyUSB0

只用 C++ 构建时，改用 ./build/native/install/lib/encos_tools/encos_usb_can。
分析仪台架保持电机断开。打开分析仪抓包，标准 CAN，速率与适配器一致，
通常按手册设 1 Mbit/s。在出现 Listening on 后输入下列命令：

  输入                          分析仪应收到（CAN ID / DLC / 数据）
  DISCOVER                      0x07FF / 4 / FF FF 00 82
  QUERY 1 VERSION               0x0001 / 2 / E1 1E
  POS 1 30                      0x0001 / 8 / 28 3E 00 00 00 32 00 2A
  CONFIG 1 ACCELERATION 20      0x0001 / 4 / C1 01 07 D0

再让分析仪发送以下标准帧。控制台无需再输入任何命令就会打印 RX：

  分析仪发送（CAN ID / DLC / 数据）                       终端字段示例
  0x07FF / 5 / FF FF 01 00 01                             management=discover status=success motor_id=1
  0x0001 / 8 / A0 1E 01 02 03 04 05 06                   query=30，硬件 1 2 3，软件 4 5 6
  0x0001 / 8 / 40 41 F0 00 00 00 00 64                   type=2，position_rad=0.523599，motor_c=25
  0x0001 / 5 / FF FE 01 07 D0                             config_echo=1 value=20

输入 EXIT 返回 Bash。无需硬件的回归演示也可在工程根目录执行：

  ctest --test-dir build/usb/encos_tools -R '^encos_usb_can_cli$' --output-on-failure

用独立 CMake 构建时，将测试目录换为 build/native/tools。用例通过伪终端
检查每条命令的真实串口写入、示例接收帧的解码和空闲收帧。

3. 可选 ROS 2 状态节点
-------------------

ROS 节点和 CLI 二选一占用同一串口。先加载第 1.2 节环境。

  ros2 run encos_driver encos_usb_can_node --ros-args \
    -p device:="$serial_dev" -p motor_id:=1

默认只监听。可以分别在其他终端查看原始帧和解码状态：

  ros2 topic echo --qos-reliability best_effort /encos/raw_rx encos_msgs/msg/RawFrame
  ros2 topic echo --qos-reliability best_effort /encos/motor_state encos_msgs/msg/MotorState

全零测试帧出现在 raw_rx。motor_state 只发布可解码的反馈，以及匹配成功的
位置、速度、相电流查询结果。只使用 valid 为真的字段。Type 1 的位置、速度和
相电流依赖核验过的量化范围，这条简化主链路尚未加载实际范围，仍按无效发布。
估算力矩也不会从未知 Kt 推导。USB 串口断开后会发布断连状态。

现场获得只读授权时，关闭上面节点后使用：

  ros2 run encos_driver encos_usb_can_node --ros-args \
    -p device:="$serial_dev" -p motor_id:=1 -p allow_queries:=true

  ros2 service call /encos/discover_motor encos_msgs/srv/DiscoverMotor '{}'
  ros2 service call /encos/read_parameter encos_msgs/srv/ReadParameter '{code: 1}'

discover 返回发现的 ID。节点的目标 ID 由 motor_id 参数指定，启动后固定。
服务响应返回匹配结果、参数值和原始帧。设备协议没有事务序列号。相同应答
签名在本节点会话内只用一次，超时或已结算后都不自动发第二次。新会话应由
操作者确认无遗留在途回复。需要持续重复查询时，应先验证设备应答寿命，
再设置允许复用的窗口。

4. 串口实现如何工作
------------------

MotorToolV1.24.zip 是厂商原始上位机包。可使用 unzip 和 binutils 查看证据，
无需运行 EXE。下面命令在项目根目录执行：

  mkdir -p build/motortool-static
  unzip -p MotorToolV1.24.zip MotorToolV1.24/MotorTool.exe > build/motortool-static/MotorTool.exe
  objdump -dw -M intel --start-address=0x403948 --stop-address=0x403999 build/motortool-static/MotorTool.exe
  objdump -dw -M intel --start-address=0x403a63 --stop-address=0x403a77 build/motortool-static/MotorTool.exe
  objdump -dw -M intel --start-address=0x40ebf0 --stop-address=0x40ec5c build/motortool-static/MotorTool.exe

串口包为 AA、两字节大端 CAN ID、包总字节数、CAN 数据、累加校验。
校验取前面全部字节之和的低 8 位。分析仪发 ID 1、DLC 8、全零数据时，
已实测 NUC 收到 AA 00 01 0D 00 00 00 00 00 00 00 00 B8。
总长度 0D 等于 DLC 8 加串口封装的 5 字节。

serial_can_transport.cpp 持有串口文件描述符，负责流式拆包、校验和只读发送
白名单，退出时恢复原参数。CLI 和 ROS 节点共享 Protocol 与 TransactionManager，
因此电机协议只实现一次。旧版 EXE 里出现的 E0 01 属于旧位置查询例，当前
电机协议继续按 V1.19EAP 的 E1 01 示例执行。已知封装没有 CAN FD/BRS 标志，
当前 USB 入口使用经典标准帧表示，实物 FD+BRS 留待验证。

5. 自动回归
-----------

  bash scripts/run_offline_tests.sh

编译并加载第 1.2 节的 ROS 2 环境后，可运行全量测试。若本机已有其他 ROS
会话，可给这轮测试单独设一个 ROS_DOMAIN_ID。

  export ROS_DOMAIN_ID=111 ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
  colcon --log-base build/colcon-test-log test --base-paths src --build-base build/usb \
    --install-base install/usb --event-handlers console_direct+ --return-code-on-test-failure
  colcon --log-base build/colcon-test-log test-result --test-result-base build/usb --verbose

预期 13 项全部通过。自动测试使用纯 C++ 协议向量、MockTransport 或 Linux
伪终端。串口用例验证分段、连包、坏校验、回显、超时、只读限制和状态发布。
命令行用例从伪终端另一端读取实际写入的字节，与手册向量逐项对照，
核对持续会话在首次命令之前、发送后和再次空闲时都能收帧，并验证回显标记、
非法命令无写入及只读查询的应答匹配。
整个过程不需要 CAN 网卡或连接电机。

6. 可选录包、接收频率分析和轨迹库
----------------------------

在第 3 节节点运行时启动录包。每次使用一个新的盘上路径，录完按 Ctrl+C 刷盘。

  ros2 launch encos_driver record.launch.py output:=data/usb_can_run_01
  ros2 bag info data/usb_can_run_01
  ros2 run encos_experiments export_samples.py data/usb_can_run_01 data/raw_01.csv --topic /encos/raw_rx
  ros2 run encos_experiments export_samples.py data/usb_can_run_01 data/state_01.csv --topic /encos/motor_state

状态 CSV 需要袋内确有可解码的电机状态。若只发全零测试帧，使用原始帧 CSV。
分析仪以 10 Hz 发 0x0001 时，可检查该 ID 的接收频率和主机接收间隔：

  ros2 run encos_experiments analyze_timing.py data/raw_01.csv --rx --hz 10 --can-id 0x0001

该结果使用主机串口接收时刻。没有序号或发送端时刻时，可统计接收速率和间隔，
无法由此计算往返延迟或准确丢包率。历史 ControlSample 录包和 CSV 仍可用原命令
导出及分析。Action 接口和独立轨迹库保留作为代码接口，当前只读节点不提供运动
执行入口。构建和回归记录放 build/，按需录制的数据放 data/。
