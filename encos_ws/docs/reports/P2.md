## 架构和实际功能

`encos_driver_node` 内的独立 C++ 线程独占 `encos_core` 的 SocketCAN、协议和事务管理器。线程按单调时钟的绝对周期采样目标、校验、编解码并处理反馈，跨过已错过的调度周期。运动事务只有一个在途，回复期限为 20 ms。读写管理事务只在允许运动前后执行，响应期限 75 ms，写后间隔和签名隔离等待有上限。控制线程不调用 DDS，也不执行日志、rosbag 或磁盘写入。

ROS Executor 处理 Topic、Service、Action 和发布。输入使用单目标邮箱和有界管理邮箱，控制线程用短临界区尝试取出。输出使用单生产者、单消费者有界队列，控制样本和调试帧各 4,096 条，状态和管理结果另有缓冲。溢出计数可从通信统计查看。Topic 以单调时钟检查原有有效期，按周期使用最近的有效目标。复用时仍保留原生成与接收时刻，发送前再检查有效期。Action 在控制线程内按实际执行时间生成设定值，支持位置、速度的保持、阶跃、正弦和线性扫频。

运行过程使用 DISCONNECTED、UNARMED、READ_ONLY、ARMED、RUNNING、STOPPING、FAULT 状态。节点启动无需发运动帧。运动前查验 ID、版本、范围、Kt、分段补偿模式、通信超时和抱闸状态。虚拟电机的可选引导反馈用于检查静止时的新鲜样本，运动应答路径不依赖该额外帧。软件授权分配只读、Topic 或 Action 控制权，Topic 绑定 owner 和有效发布者的 DDS GID。Action 排斥 Topic，受保护写入与运动互斥。写入默认关闭，指定启动开关后每一项仍需明确确认。

命令或安全反馈过期、回复超时、反馈越限、过温或电机故障触发停发和锁存。正常停止、Action 完成或取消都撤销控制权。驱动等待虚拟看门狗生效，再读取速度确认。故障恢复需显式复位并重新授权，停止请求不能清除已锁存故障。固件使能、软件授权、停发、零电流、制动和独立硬件急停各自有不同含义。P2 的停止证据是虚拟电机的速度读回。

## ROS 2 接口

| 接口 | 实现 |
|---|---|
| Topic | `/encos/motor_command`、`/encos/motor_state`、`/encos/control_sample`、`/encos/communication_stats`、`/encos/fault`、`/joint_states`。启用 `publish_raw` 后可订阅只读的 `/encos/raw_tx`、`/encos/raw_rx`。 |
| 查询 Service | `/encos/discover_motor`、`/encos/read_parameter`、`/encos/get_profile`。状态快照可在运动期间读取，CAN 查询需等待无运动。 |
| 授权和故障 Service | `/encos/arm`、`/encos/stop`、`/encos/reset_fault`。Arm 表示 ROS 软件控制权。 |
| 配置 Service | `/encos/write_parameter`、`/encos/set_zero`、`/encos/set_motor_id`、`/encos/reset_motor_id`、`/encos/set_brake`。区分报告回显和读回验证，对有歧义的配置显式拒绝或保留原始回显。 |
| Action | `/encos/run_experiment`。有目标参数、进度、发送样本数及成功、取消、故障终止结果。 |
| 运行参数 | `can_interface`、`fd_brs`、`motor_id`、`control_hz`、`motor_model`、`joint_name`、`publish_ms`、`safety_feedback_ms`、`publish_*`、`allow_virtual_*` 和 `limits.*`。启动时校验并固定。 |

控制 Topic 使用 Best Effort / Keep Last 1，有效期不会随 DDS 交付或复用刷新。状态和原始帧为 Best Effort，控制样本、统计和故障为 Reliable，故障另用 Transient Local。消息字段、YAML、QoS 和可执行命令见 [P2 操作指南](../ros2_p2.md)。

位置、速度、相电流、估算力矩和温度分别使用 rad、rad/s、A、Nm、°C。混控范围来自虚拟响应核验，并与型号额定值和软件限值分开。类型 2/3 缺失的量带无效标志和 NaN。将 ROS 源时间与 ROS 接收时间分别保留，并保存单调调度、实际周期间隔、TX 调用前后、内核软件 RX 实时钟、换算的 RX 单调钟、用户态读取、解析和 Executor 发布时刻。物理线路时刻、内核 TX 时刻和电机内部采样时刻未知。估算力矩记录其相电流与 Kt 来源。`/joint_states` 只填充有效位置和速度。

## 性能与 P1 对比

A 为 Action 在控制线程内生成目标并发布测量。B 为独立 C++ ROS 发布器加状态监控。C 同时记录 rosbag2 的状态、故障、统计及控制样本。D 额外监控并录制原始 CAN，订阅状态、统计和诊断。E 使用 B 的 Topic 发送方式，加状态和原始帧监控，按 2 ms 定时提交诊断快照请求，最多四个在途。通信故障另在集成测试注入。B–E 的源发布目标为 CAN 目标频率的两倍。各工况 10–200 Hz 的预定时间为 2.5 s，400 Hz 为 61 s。经典和 FD 分别固定在两组逻辑 CPU，且扫描同时进行，计入各自的宿主机调度影响。测量命令为：

## rosbag2 完整性和原始证据

## 保留的失败及修正

- 首次 Jazzy 构建 FAIL。GCC 报两个 64 位整数表达式的类型不一致，修正显式类型转换后重新编译。[首次构建](../../logs/p2/build-first.log)
- 前两轮 400 Hz 保留为 FAIL。第一轮的每目标单次消费造成周期缺口。经典 CAN 的 B–E 只有 360.08–373.03 Hz，FD 的 B–E 为 295.42–316.73 Hz。改成固定周期采样仍有效的最新目标后，第二轮的活跃区间均超过 396 Hz，仍有 7 个工况提前过期锁存，CAN 回复超时为 0。最后把高频发布改为独立 C++ 进程，记录每次实际发布时刻，10 个 400 Hz 工况都完成至少 60 秒。过期后停止的规则继续由集成测试验证。[首次经典](../../logs/p2/performance-classic/) · [首次 FD](../../logs/p2/performance-fd/) · [第二轮经典](../../logs/p2/hold-classic/) · [第二轮 FD](../../logs/p2/hold-fd/)
- 新增退出用例的首次 FD 重启检查读到了上一进程的 DDS 样本。SIGKILL 后 DDS 还可能保留旧端点直至租约结束。测试改为等待新驱动发布已连接的 UNARMED，再用 Service 读回速度。最终经典 SIGINT 和 FD SIGKILL 两路均通过。[旧状态](../../logs/p2/colcon-test-final.log) · [旧端点](../../logs/p2/colcon-test-validated.log)
- 一次零点写入得到回显但读回超时。旧间隔起点是主机发送，模拟端从处理帧起计时。改为收到回显后等满 500 ms，并补了匹配回显与无回显情况下的时间边界回归。第一次更新回归时遗漏了后续制动断言的测试时刻，修正后重跑。[读回失败](../../logs/p2/colcon-test-verified.log) · [边界测试初次失败](../../logs/p2/colcon-test-release.log)
- ASan 构建曾额外执行 50 Hz Topic 性能预检。132 笔事务均成功，发送程序完成发帧后仍在退出，测试编排等待进程结束才调用 Stop，驱动因目标过期锁存。本预检为 FAIL，无 sanitizer 诊断，记录单独保留。ASan 功能和故障验证用 CTest。[附加预检](../../logs/p2/asan-topic-smoke/50hz_B/summary.json)
- CLI 教程首轮遇到状态 Topic 类型发现滞后。后续批处理还验证了录包必须正常收到 SIGINT 才能刷盘，取消请求要等 Action 已收到反馈，后加入的故障订阅者需要显式 Reliable 和 Transient Local。按照修订后的命令重新验证通过。[早期 CLI 输出](../../logs/p2/tutorial-complete.log) · [最终 CLI 输出](../../logs/p2/tutorial-pass.log)

## 实机未决事项和 P3 准入

- 供电须由厂商按本型号、具体硬件和固件书面确认。数据手册额定 72 V，调试手册 §3.4 列 20–57 V 且提示 60 V 以上可能损坏。现场负责人核验限流、再生能量吸收、独立急停和固定空载输出端。
- 现场清点可用的 Linux SocketCAN 适配器、驱动及固件，确认电源和通信针脚、极性、CAN_H/CAN_L、参考地、隔离、终端电阻和单电机接线，断电完成接线。接口名、帧型、仲裁速率、数据速率和采样点须和厂商配置匹配。V1.19 示例为 1 Mbit/s、76.5% 仲裁采样点，FD+BRS 数据 5 Mbit/s、88.2% 采样点。实际适用值仍待现场确认。
- 核对 ID、实际固件/硬件版本、量化范围、Kt 及补偿模式、通信超时动作、温度保护和抱闸是否装配。准备现场批准的只读查询清单、人工授权记录、报文捕获路径和异常停止流程。保持写入与运动隔离。当前程序需要独立的 P3 只读访问方案和验收；启动静止反馈、设备迟到上界以及物理失能机制也需要厂商确认。
- 软件状态模型、数据记录和虚拟测试已完成。只有现场准备和用户审核均通过，才具备 P3 实机只读操作的准入条件。[现场检查清单](../hardware_checklist.md) · [协议待确认项](../open_issues.md)
