## 实现

- `SocketCanTransport` 通过 rtnetlink 在绑定前后验证接口为 `vcan`，核查 UP 和 MTU，拒绝物理接口。发送是非阻塞系统调用，接收用有界 `ppoll`，`eventfd` 可中断等待。文件描述符由 RAII 清理。发送与接收可并发，第二个接收者得到 busy。保留 FD+BRS、ESI、错误标志、SocketCAN 内核软件时间戳和接收队列溢出计数。标准 ID 和数据帧过滤经两端独立 socket 验证。
- 禁用当前 socket 自己的发送回环接收。来自另一 vcan socket 的报文作为逻辑对端帧。用间隔不超过 5 µs 的两次单调时钟读数夹住实时钟读数，校验换算偏移。迟到判定使用从内核接收时间换算的单调时刻。时间戳缺失、换算不可靠或检测到时钟跳变时不将来源标为可匹配对端。CSV 同时保存内核实时钟、估计的单调接收时刻、用户态读取和来源。
- 虚拟电机接收指令后维护合成位置、速度、相电流、温度、故障、配置、ID 和抱闸状态。位置目标可直接到达，速度按单调时间推进，停止时清零速度和相电流。电流、力矩、制动只模拟可重复的控制状态。控制帧在内核排队超过 50 ms 时丢弃。运动看门狗使用模拟超时值。改 ID、零点、通信模式后遵守 500 ms 间隔。
- 独立 CLI 发查询及受保护的虚拟位置/速度指令。示例 CLI 查询 ID、版本、量化范围和参数，取得模拟初始反馈后才授权。独立观察器记录双向帧。基准程序按绝对单调时刻生成并编码目标，交替验证正负位置，超期跳过调度周期，测量循环结束后才写 CSV。
- 复用 P0 的事务签名和默认隔离。基准使用专用虚拟链路的一次成功应答约定，只复用已成功且恰好发一帧的遥测签名，任何失败后结束本轮。故障测试使用单独的事务边界，迟到帧不能凭相同 ID 或反馈类型完成另一事务。真实设备迟到边界仍待确认。

保留的中间失败及修正：

- 第一轮端到端测试，越限用例把两个 `Clock::now()` 分别放进函数实参，GCC 可能先取验证时间再取生成时间，触发了过期分支。将生成时间显式先保存，重新验证了越限锁存。[首次日志](../../logs/p1/standalone-tests.log)
- TSan 首次启动遇到 `unexpected memory mapping`。改用 `setarch -R` 限定在被测进程。重跑还暴露并发用例本身的探针竞争，辅助等待线程有时会先得到 busy。修正测试探针后，最终版重复通过。[TSan 首次日志](../../logs/p1/tsan.log)
- 中途 400 Hz 经典 CAN 扫描在约 0.913 秒锁存一次超时。CSV 仍捕获到了最终回复，往返约 105 µs，模拟端发送 357 次且无队列丢失。失败行的时间偏移与连续成功行不一致，与换算采样被抢占相符。缩短配对采样窗口、过滤过长采样并增加 CSV 用户态时间戳和来源字段后，完整扫描通过。失败结果保留。[该轮 CSV](../../logs/p1/performance-final/classic_400hz.csv) · [模拟端日志](../../logs/p1/performance-final/classic_400hz_motor.log)

## 阶段判定

P1 虚拟链路技术验收通过。完整扫描覆盖两种帧型和七档频率。400 Hz 单独复测各持续 60.998 秒，经典 CAN / FD+BRS 的有效反馈为 399.392 / 399.261 Hz，实际已发送帧的反馈丢失率均为 0，跳过周期分别为 38 和 46。P2 须经用户审核后开始。

实机使用的量化范围、供电、工作温度、抱闸、再生吸收、超时后动作、停止策略及迟到上界仍待厂商或现场确认。加速度配置、通信模式特殊回显和补偿相关歧义继续隔离。自动化验证只有虚拟和离线路径。当前停在 P1。
